# Audience pages: SEO keyword plan (draft, M1)

Status: planned. Nothing is live. Keywords are candidates to be checked with real search data (Google Search Console
after launch, a keyword tool before it) and trimmed to what we can honestly rank for and deliver.

## How the keywords are used (read this first)

- Google ignores the old `<meta name="keywords">` tag, so we do **not** use it. Keywords work through the **title, meta description,
  one H1, section headings, body text, example questions, image alt text, internal links and the FAQ** on each page.
- **One main keyword per page** goes in the title, H1 and first paragraph. The other 49 or more are secondary terms and
  long-tail questions that appear **naturally** in headings, the FAQ, the example questions and the template cards. Stuffing a page
  with a list of keywords is penalised; each term must read as normal writing.
- Indexing is not caused by keywords. A page gets indexed when it is crawlable, in the sitemap, has unique useful text, a
  canonical URL and is linked from other pages. The M1 build already does these through the SEO step
  (`scripts/seo-prerender.mjs`: static HTML, sitemap, canonical). Keywords help it **rank** once indexed.
- Keywords never promise what the product does not do (no ordering or payments for food, no legal-binding elections,
  small groups are withheld, never shown as zero).
- Targets: at least 50 keywords per page. Every list below has 50 or more; the count is checked by a script before the build.
